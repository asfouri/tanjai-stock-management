Presenter summary: The project replaces fragmented spreadsheet operations with a central, role-aware system. Its strongest implemented capability is the Excel preview-and-confirm pipeline; production readiness now depends on data validation, deployment hardening, integration testing and reducing concentration in three very large files.

Problem addressed

Operational data is spread across quotation, store-order, stock, invoice and payment sheets. Matching SKUs, tracking shipments and reconciling costs require repeated manual work.

Project objective

Parse the workbook safely, preview issues, persist confirmed data, and expose a role-aware dashboard for products, stores, orders, invoices, payments and integrations.

Verified users

TanjAI Admin operates imports and users; Brand Owner sees assigned stores and manages commerce connections; UFULFILL works with products and operations while cost visibility is reduced.

Implemented in code

Core capabilities

  • Supabase/local-development authentication and role-aware navigation.
  • Excel parsing, sheet classification, preview, warnings, duplicates, confirmation, removal, replacement and refresh.
  • Dashboards for products, orders, stores, invoices and payments.
  • User management, deposit requests and shipment tracking model.
Requires validation

Current limitations

  • No live database or workbook was available to calculate business record counts.
  • External integrations are implemented/configurable but were not called during this static audit.
  • No Prisma migrations directory; schema rollout relies on SQL scripts.
  • Large frontend/import/dashboard services raise change and regression risk.
Current status: a substantial working application with production-oriented flows, but not independently certified production-ready by this analysis. Runtime integrations, real data quality, deployment and end-to-end authorization still require environment-based testing.

Frontend

Next.js 16.2.9 App Router with React 19.2.4 and TypeScript 6. The dashboard is client-rendered; server routes proxy local backend traffic and integration callbacks.

Backend

NestJS 11 on Express, organized into one application module, one API controller, domain services, guards and Prisma infrastructure.

UI

Tailwind CSS 4 via PostCSS styles the application. Recharts 3.8 renders dashboard bar, line and pie charts.

Persistence

PostgreSQL with Prisma 6.19 and the PostgreSQL adapter. Prisma models use the public schema and reference Supabase's auth schema configuration.

Authentication

Supabase Auth supplies browser sessions; the backend validates bearer tokens through the Supabase service API. A deliberately gated local-development token path also exists.

Excel processing

A custom in-repo OpenXML/XLSX parser reads workbook ZIP parts, rows, shared strings and embedded images. There is no external spreadsheet package dependency.

Development

npm lockfiles, TypeScript, ESLint 9, Prettier (backend), Jest 30 and ts-jest. Nest CLI and Next CLI provide builds and local servers.

External services

Native fetch implementations connect Shopify OAuth/order sync, WooCommerce REST/webhooks and 17TRACK registration/status webhooks.

Tunnelling & deployment

Environment examples include public callback URLs and references to ngrok/Cloudflare-style tunnels. No deployment manifest, container file or CI workflow was found.

4. Orders, shipments, invoices and inventory Implemented in parser

Store-order sheets generate stores, orders, lines, shipment records and fulfilment invoice blocks. Stock invoice sheets generate purchases; stock list sheets generate inventory items, links and movements; payment-balance sheets generate wallet transactions and stores.

Risks: unknown stores, invalid dates/tracking numbers, unmatched SKUs and unrecognized rows produce warnings; unknown sheet types are recorded but not imported.

5. Shopify connection and sync Runtime unverified

Brand Owner starts installation → pending nonce cookie → Shopify launch/HMAC verification → OAuth callback/state verification → encrypted token persistence in ShopifyConnection → manual sync imports orders/fulfilments. Required environment keys and a reachable callback URL are prerequisites.

6. WooCommerce connection, sync and webhooks Runtime unverified

Brand Owner starts connection for an assigned store → pending connection → credentials callback → encrypted credentials → webhook creation → order sync. Public webhook requests are mapped by connection public ID and verified with the stored secret before order changes are processed.

7. Shipment tracking Runtime unverified

Admin may bulk-register pending shipments; authenticated users may register/refresh accessible shipments. 17TRACK responses update shipment status and normalized tracking data. Signed webhooks create deduplicated ShipmentTrackingEvent records.

8. User management Implemented

Admin lists Supabase users and store options, creates users with validated roles, assigns stores to Brand Owners, updates identity/role/password, and deletes accounts. Self-deletion and removal of the last admin are guarded.

Persistence model

21 Prisma models across five business domains

Catalog & stores

Brand → Store; Product → ProductSkuAlias / ProductAlias; InventoryItem → InventoryProductLink → optional Product.

Commerce & fulfilment

ImportBatch → Order → OrderLine / Shipment → ShipmentTrackingEvent; Store and optional WooCommerceConnection scope orders.

Finance & operations

FulfillmentInvoice, StockPurchase, InventoryMovement, WalletTransaction and DepositRequest capture workbook and user-entered financial operations.

All models and key constraints

Import: ImportBatch (unique fileHash), Anomaly. Catalog: Brand (unique name), Store (unique brand + normalizedName), Product (unique name), ProductSkuAlias (globally unique SKU), ProductAlias (globally unique normalizedName). Sales: Order (store/order/invoice and provider/external IDs), OrderLine, Shipment (public ID, tracking compound unique), ShipmentTrackingEvent (shipment/fingerprint unique). Operations: FulfillmentInvoice, StockPurchase, InventoryMovement, InventoryItem, InventoryProductLink. Finance: WalletTransaction, DepositRequest. Integrations: ShopifyConnection, WooCommercePendingConnection, WooCommerceConnection.

Data-quality watch points: ProductSkuAlias is globally unique even though it optionally belongs to a store; Product and ProductAlias also use global name uniqueness. Several operational links intentionally allow null Product/Store references, preserving rows but weakening referential completeness. JSON fields retain source/integration flexibility at the cost of database-level validation.

Matching order

  1. Canonical quotation product and SKU maps.
  2. Deferred SKU Decoder aliases.
  3. Known stock-name mappings.
  4. Exact normalized quotation name (confidence 0.95).
  5. Component-token match (0.82).
  6. Loose/fuzzy variant match (0.72).
  7. Unmatched SKU-only fallback product and warning.

Validation and persistence

  • SHA-256 file hash detects identical imports.
  • Preview returns summary, up to 50 warnings and duplicate records.
  • Temporary preview data is held in process memory.
  • EXCEL_IMPORT_STORAGE=prisma uses a Prisma transaction; other values write local compressed JSON.
  • Refresh can fully replace or incrementally diff rows; auto-refresh polls a configured shared folder.
  • Quotation images are embedded as data URLs and persisted in Product.imageUrl.
Manual validation focus: low-confidence inventory matches, changed sheet headers/names, unknown sheets, SKU collisions across stores, SKU-only fallback products, unrecognized dates, missing tracking numbers and rows omitted by parser assumptions.

TanjAI Stock ManagementExecutive presentation
01 · Problem

Spreadsheet operations do not scale cleanly.

Products, orders, stock, fulfilment invoices and payments arrive in different sheets and formats. Manual matching creates delays, inconsistent identifiers and weak traceability.

02 · Solution

Parse once. Validate. Centralize. Operate.

TanjAI converts workbooks into relational data, surfaces warnings before confirmation, and gives each role an operational dashboard.

03 · Users

Three verified roles.

  • TanjAI Admin — imports, users and full oversight.
  • Brand Owner — assigned stores, commerce integrations and commercial data.
  • UFULFILL — products and operations with reduced cost visibility.
04 · Main features

From catalog to last-mile tracking.

Excel preview/confirm, product and SKU matching, orders, inventory, invoices, payments, deposits, users, Shopify, WooCommerce and 17TRACK foundations.

05 · Architecture

Next.js → NestJS → Prisma/PostgreSQL.

Supabase validates identity. A custom OpenXML engine creates the core dataset. External services extend orders and shipment status through OAuth, REST and signed webhooks.

06 · Excel flow

Workbook → preview → warnings → confirmation.

Quotation, SKU Decoder, store orders, stock invoices, stock lists and payment-balance sheets map into 21 database models. Low-confidence matches remain a manual validation priority.

07 · Current metrics

72 files · 22,901 lines · 50 API routes.

21 Prisma models, 3 roles, 3 business integrations and 36 example environment keys. Live product/order totals were unavailable and are intentionally not estimated.

08 · Demonstration workflow

Login → import preview → dashboard → order → shipment.

Show role-aware navigation, upload a sanitized workbook, inspect warnings, confirm, filter an order, then open tracking and integration status.

09 · Achievements

Manual reconciliation is now an application workflow.

Data is centralized, source rows are traceable, duplicate files are detected, product matching is layered, and store access is represented in code.

10 · Limitations

Strong implementation, incomplete production proof.

No live database/workbook metrics in this audit; integrations need staging verification; migration history is absent; three large files concentrate 60.9% of measured code.

11 · Next steps

Prove data, permissions and deployment first.

Run staging authorization tests, baseline migrations, validate golden workbooks, exercise all external integrations, then reduce large-file concentration and add CI/observability.
